# 竞赛雷达 MCP：规划

> 状态：首版设计定稿（2026-10-25）
> 目标读者：实现者 / 后续维护者

## 1. 目标

把分散在竞赛聚合站与官方名录里的信息，整理成一个可被 AI 客户端直接调用的 MCP 服务，支持：

- 按关键词、类别、级别、状态、截止时间检索竞赛；
- 查看单个竞赛的结构化信息与正文详情；
- 浏览官方认可竞赛名录（84 项核心赛事的官网与别名）；
- 缓存与增量刷新，避免每次对话重复抓取。

首版侧重「通用搜索与详情浏览」，同时保留报名截止筛选能力，方便后续接周报工作流。

## 2. 范围

### 2.1 首版包含

| 数据源 | 角色 | 接入方式 |
| --- | --- | --- |
| 赛氪（saikr.com） | 主源：结构化竞赛列表、搜索、详情 | 匿名 JSON API |
| 我爱竞赛网（52jingsai.com） | 补充源：榜单竞赛、截止摘要、详情正文 | GBK HTML 解析 |
| 官方竞赛目录 | 权威标注：84 项核心赛事、官网链接 | 静态 JSON（年度更新） |

### 2.2 首版不包含

- 微信公众号、小红书、QQ 群等封闭渠道；
- Kaggle / Devpost / ICPC 等国际平台（接口与字段差异大）；
- 对 84 个官网逐个抓取赛程（首版只提供官网链接，后续按需增加重点站点适配器）；
- 自动生成周报文案（首版返回结构化候选集，文案由调用方生成）。

### 2.3 非目标

- 不做用户账号、报名代操作、成绩查询；
- 不绕过登录、验证码或付费墙；
- 不做大规模全量镜像，不对外再分发抓取内容。

## 3. 总体架构

```text
MCP client (Qoder / Web backend / CLI)
        │  stdio / Streamable HTTP / SSE
        ▼
┌──────────────────────────────────────────┐
│ MCP server (TypeScript)                  │
│  tools: search / get / deadlines / ...   │
└───────────────┬──────────────────────────┘
                │
        ┌───────▼────────┐
        │ Competition    │  归一化、状态计算、去重、
        │ service        │  官目录匹配、缓存策略
        └───┬────────┬───┘
            │        │
   ┌────────▼──┐  ┌──▼─────────────┐
   │ adapters  │  │ SQLite cache    │
   │ saikr     │  │ competitions    │
   │ jingsai52 │  │ details         │
   │ catalog   │  │ catalog         │
   └─────┬─────┘  │ source_state    │
         │        └─────────────────┘
         ▼
   外部 HTTP（低频率、可关闭）
```

### 3.1 关键设计

1. **适配器隔离**：每个来源只负责「抓取 + 解析成原始条目」，统一字段与业务判断放在 service 层。
2. **缓存优先**：MCP 工具默认读 SQLite；搜索时可对赛氪做一次在线补充，失败则回退缓存并返回 `errors`。
3. **详情按需拉取**：列表只存摘要；`get_competition` 首次访问时抓详情并缓存，避免全量抓正文。
4. **官方目录独立**：静态 JSON 随仓库发布，不依赖在线抓取；用于 `official` 标记与官网 URL 补全。
5. **可降级**：任一源失败不影响其他源；工具返回结构化错误，不抛裸异常。
6. **限流与缓存**：赛氪请求间隔 ≥1.5s，列表缓存 12h，详情缓存 7d；我爱竞赛网间隔 ≥2s。

## 4. 数据流

### 4.1 搜索

```text
query + filters
  → 查本地 competitions（LIKE / 过滤 / 排序）
  → 若 query 非空且允许 live：调赛氪 search API（最多 50 条）
  → upsert 到 SQLite
  → 合并、跨源去重、官目录匹配
  → 返回摘要列表 + 抓取告警
```

### 4.2 详情

```text
id → 查 details 缓存（7 天内）
   → 未命中：按 source 抓详情
   → saikr: api/pc/contest/info
   → 52jingsai: article-<id>-1.html
   → 提取正文、报名时间、主办方、官网、费用线索
   → 缓存并返回
```

### 4.3 刷新

```text
refresh_data(source, max_pages)
  → 赛氪：按 class/level 拉列表（默认 3 页 × 100）
  → 52jingsai：按配置频道拉列表（默认 6 频道 × 3 页）
  → 官方目录：读取本地 JSON
  → upsert + 记录 source_state
```

## 5. MCP 接口（首版）

| 工具 | 用途 |
| --- | --- |
| `search_competitions` | 关键词 + 类别/级别/状态/截止天数筛选 |
| `get_competition` | 单条详情，含正文与官目录匹配 |
| `list_deadlines` | 指定天数内报名截止的竞赛 |
| `search_catalog` | 查官方 84 项名录，按名称/月份/类别 |
| `list_sources` | 数据源状态、上次同步、能力与限流 |
| `refresh_data` | 主动刷新指定源（默认关闭详情抓取） |
| `get_stats` | 缓存数量、状态/类别分布、最近同步 |

详细输入输出契约见 [SCHEMA.md](./SCHEMA.md)。

## 6. 里程碑

1. **M1 文档与骨架**：规划、信源、Schema；TypeScript 工程与 SQLite 初始化。
2. **M2 适配器**：赛氪列表/搜索/详情、52jingsai 列表/详情、官方目录加载与匹配。
3. **M3 MCP**：7 个工具、stdio 入口、可选 HTTP 入口。
4. **M4 验证**：fixture 解析测试、状态/日期/去重单测、真实接口冒烟。
5. **M5 交付**：README、客户端配置、已知限制与维护说明。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 赛氪内部 API 变更或封禁 | 主源不可用 | 适配器版本化；失败降级；可一键禁用；保留 52jingsai 与官目录 |
| robots 限制（赛氪 `/api/`、带查询串路径） | 合规风险 | 仅个人低频使用；默认小页数；缓存优先；文档明示；不对外分发 |
| 我爱竞赛网标题营销化 | 检索噪声 | 归一化标题；官方目录匹配；保留原始标题 |
| 日期缺失或仅正文提及 | 截止筛选不准 | 字段缺失即 `unknown`，不猜测；正文线索单独返回 |
| 同一赛事多源重复 | 结果重复 | `canonical_key` 归一化 + 查询时跨源合并 |
| 官方目录年度变化 | 权威标注过期 | 目录带版本号；每年人工复核一次 |

## 8. 验收标准

- `npm run build` 与 `npm test` 通过；
- stdio 模式可被 MCP 客户端拉起，`tools/list` 返回 7 个工具；
- 真实网络下：赛氪关键词搜索、详情、52jingsai 列表、官目录查询均返回非空；
- 断网时：已缓存数据仍可搜索/查看，工具返回可读的 `errors`；
- 同一赛事在赛氪与 52jingsai 同时出现时，搜索结果合并为一条并保留来源链接。
